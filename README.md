## Практическая работа №3

### Защита состояния Hero

**Почему методы ПР №2 не защищали от прямой записи в поле:**
  Потому что поля класса оставались открытыми (public). Любой внешний код мог выполнить команду вроде alexander.Health = -100; напрямую, минуя метод TakeDamage() и заложенные в него проверки.

**Чем отличаются get, set и private set:**
get открывает свойство для чтения внешним кодом. set разрешает внешнему коду свободно записывать любое значение. private set полностью запрещает запись снаружи класса, позволяя менять свойство только изнутри.

**Где проверяется начальное здоровье:**
Начальное здоровье проверяется в конструкторе public Hero(string name, int health) сразу после валидации и установки личного предела MaxHealth.

**Как Heal сохраняет границу MaxHealth:**
Метод сначала вычисляет дефицит здоровья (missingHealth = MaxHealth - Health). Если величина лечения amount больше или равна этому дефициту, метод жестко присваивает Health = MaxHealth; и сразу завершает работу, предотвращая переполнение.

**Как Name использует поле _name и значение value:**
Закрытое поле _name непосредственно хранит строку в памяти. При записи в свойство ключевое слово value содержит передаваемую строку. Блок set проверяет value, очищает его с помощью .Trim() и записывает очищенный результат в _name. Блок get просто возвращает значение из поля _name.

**Почему в конструкторе используется Name = name:**
  Чтобы присваивание прошло через свойство и автоматически запустило блок set. Если бы мы написали _name = name;, то присвоение произошло бы в обход сеттера, и имя персонажа сохранилось бы со всеми исходными пробелами и дефектами.

### Исправление ошибок

1. **Ошибка, исправление, проверка:**
Ошибка: Свойство здоровья полностью открыто: public int Health { get; set; }.
Исправление: Заменили сеттер на закрытый: public int Health { get; private set; }.
Проверка: Прямая запись извне заблокирована компилятором, данные защищены.
2. **Ошибка, исправление, проверка:**
Ошибка: Результат очистки строки не сохранялся: value.Trim(); _name = value;.
Исправление: Изменили на присвоение возвращаемого значения: _name = value.Trim();.
Проверка: Имя "Александр" стало успешно очищаться до [Александр].
3. **Ошибка, исправление, проверка:**
Ошибка: Перепутан знак фильтрации лечения на входе в Heal(): if (amount >= 0) { return; }.
Исправление: Заменили условие на отсечение неположительных чисел: if (amount <= 0) { return; }.
Проверка: Для героя со здоровьем 100 после TakeDamage(30), Heal(10) и Heal(-10) итоговое здоровье составило 80.
4. **Ошибка, исправление, проверка:**
Ошибка: Лечение наносило урон из-за неверного оператора: Health -= amount;.
Исправление: Поменяли оператор вычитания на сложение: Health += amount;.
Проверка: При исходном здоровье 100, получении урона 30 и лечении 10 здоровье корректно увеличилось до 80.
5. **Ошибка, исправление, проверка:**
Ошибка: При максимальном исцелении присваивалось некорректное число: Health = amount;.
Исправление: Изменили на присвоение верхней допустимой границы: Health = MaxHealth;.
Проверка: Для героя с пределом 150 после урона 30 и лечения 5000 здоровье на выходе составило строго 150.

### ПР №3. Инкапсуляция собственного класса

**Класс и его назначение:**
Класс Game представляет модель видеоигры в каталоге, которая отвечает за надежное хранение информации о названии, жанре, годе выпуска и оценках пользователей.

**Какие данные защищены и почему:**
Защищены свойства Title, Genre, ReleaseYear и Rating. Это исключает появление в базе некорректных данных, которые могли быть случайно записаны внешним кодом.

**Какие свойства имеют private set:**
  Свойства Genre, ReleaseYear и Rating снабжены модификатором private set для предотвращения несанкционированного прямого редактирования.

**Какое свойство использует закрытое поле:**
  Свойство Title работает в связке с приватным полем _title, выполняя валидацию строк.

**Что проверяют конструктор и методы:**
Конструктор проверяет название и жанр на пустоту, ограничивает минимальный год релиза (не раньше 1950) и удерживает рейтинг строго в границах от 0.0 до 10.0.
Метод UpdateRating проверяет новые оценки на попадание в допустимый диапазон [0.0; 10.0] и полностью игнорирует вызовы с некорректными числами.

**Проверки двух объектов и полученные результаты:**
persona: Исходное имя "Persona 3 Reload" успешно очищено от краевых пробелов rightarrow [Persona 3 Reload]. Метод UpdateRating(9.5) штатно обновил рейтинг с 10.0 до 9.5.
zelda: Вызов метода UpdateRating(15.0) был полностью отклонен защитой, рейтинг остался стабильным и безопасным (10.0).
Изменение рейтинга у объекта persona никак не затронуло объект zelda - их состояния полностью независимы. Прямое присвоение извне persona.Rating = -5.0; не компилируется.
